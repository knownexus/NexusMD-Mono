# Accounts, Config and Device Restore (Milestone 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An invite-only, multi-user account on a NexusMD server (Railway) so that logging in on a new Windows or Android install restores all configuration, secrets and per-device preferences, end-to-end encrypted under the user's password.

**Architecture:** The ASP.NET server stores users, invites, sessions, devices and opaque encrypted items in SQLite, and never sees a vault key or plaintext. A shared client library in `@nexusmd/core` derives keys (PBKDF2 -> auth key + vault key), encrypts each synced setting as an item under a per-user container key, and runs a snapshot-diff sync engine (collect localStorage + secure storage, push changed entries, pull the change feed). A gate in `@nexusmd/ui` handles login / invite / device pick; desktop and Android wire it in.

**Tech Stack:** ASP.NET Core 8 + Microsoft.Data.Sqlite + JwtBearer + xUnit (`apps/web/server`, `apps/web/server-tests`); plain JS/JSX, WebCrypto, vitest + React Testing Library (`packages/core`, `packages/ui`, `apps/desktop`, `apps/app`); Docker + Railway.

**Spec:** `docs/superpowers/specs/2026-11-01-accounts-and-sync-design.md` (Milestone 1 only; M2 data sync and M3 sharing are separate plans).

## Global Constraints
- Key derivation: PBKDF2-HMAC-SHA256, **>= 600000 iterations** in production (client enforces `MIN_ITERATIONS = 600000` unless a test passes a lower `minIterations`); 64 bytes derived, HKDF-split into an **auth key** (sent to server) and a **vault key** (never leaves the device). Do not reuse the SHA-256 helpers in `confidential.js`, `bundle.js`, `settings-file.js`.
- The server stores only: salt, iteration count, a hash of the auth key (PBKDF2 with its own salt), wrapped keys, public key, ciphertext. It must never receive the vault key, container key, or plaintext values. Item ids are opaque (HMAC of the setting name), so setting names are not visible either.
- Invite-only: no public sign-up. First (admin) account only via `POST /api/account/setup` with env `Accounts:SetupToken`.
- JWT access token 15 min (`Jwt:AccessMinutes`), rotating hashed refresh tokens; reuse of a rotated refresh token revokes that session. Lockout: 5 failed logins -> locked 15 min.
- Item size cap `Items:MaxBytes` default **26214400** (25 MB).
- Server config keys: `Accounts:DbPath`, `Accounts:SetupToken`, `Jwt:SigningKey` (>= 32 bytes; startup fails if missing outside Development), `Web:LegacyEndpoints` (default false).
- Android namespace is `helm`, desktop/web `nexusmd`; commits follow `feat(scope): ...`; no emojis in code or docs.

## Decisions that differ from or extend the spec (flag to the user at handoff)
- **Legacy endpoints are gated, not authenticated:** `Ado`, `Config`, `Files`, `Profiles` controllers return 404 unless `Web:LegacyEndpoints=true`. They are single-tenant and unauthenticated, serve only the web SPA (out of scope), and would be an open hole on a public Railway host. Per-user rework happens with the web milestone. OAuth controllers (`/api/google/auth`, `/api/ms/auth`) stay anonymous.
- Refresh tokens are per login session, not per device; devices are chosen after login.
- Device names are stored in plaintext so the login device picker can show them; device preferences themselves are encrypted.
- Sync is a **snapshot-diff** (periodic collect, hash compare, push changed, pull change feed) instead of hooking every write; per-entry last-writer-wins. On a device's first sync, a key present both locally and remotely takes the remote value; local-only keys are pushed.
- A "Use without an account" link keeps the app usable locally and offline (my call).
- Items for tokens keep their platform namespace in the id, so a Windows Google token and an Android Google token are separate items (resolves the OAuth client-binding gotcha). Connection settings (ADO/GitHub/Jira), the profile list and appearance use platform-neutral ids.
- Data keys (planner weeks, notes, calendar events, lists, time log) are excluded in M1; M2 moves them.

## Review Focus
- Wrong password / unknown username must look identical to the caller (no user enumeration; `params` returns a stable fake salt for unknown names).
- Device with no network and a stored session still opens the app and syncs later; a revoked session sends the user back to login without wiping local data.
- Sync must not delete local data when the server returns an empty change feed or the first pull fails.
- A key removed locally propagates as a tombstone; a key removed remotely is removed locally only if unchanged locally since last sync.
- Android with an existing local profile logging into an account with other profiles ends up with the union (by id), not a replacement.
- Items from another user or another user's device are never readable (404, not 403).
- Secure-storage values and `nexusmd.sec.account.*` (session, container key) never appear in `.nmdsettings` exports or as synced items.
